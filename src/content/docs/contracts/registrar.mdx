`ManagerSigRegistrar` adds a member to a Reserve when an account holding that Reserve's `USERS` permission has signed the member's leaf. Anyone can submit the signed registration. One instance serves every Reserve that grants it `USERS`.

## Setup

A Reserve uses the registrar after two grants by its admin:

1. `grantPermission(USERS, registrar)`, so the registrar can call `Reserve.addUser`.
2. `grantPermission(USERS, signer)` for each account whose signatures it should accept. The admin holds `USERS` implicitly and can sign without a grant.

Each signature names its signer, so several signers can serve one Reserve.

## The signed message

The registrar uses EIP-712:

| Part | Value |
| --- | --- |
| Domain type | `EIP712Domain(string name,string version,uint256 chainId,address verifyingContract)` |
| `name` | `MistReserveRegistrar` |
| `version` | `3` |
| `chainId` | `block.chainid`, read on every call, so a chain fork gets its own domain |
| `verifyingContract` | The registrar's address |
| Struct type | `RegisterUser(address reserve,uint256 leaf,uint256 leafNonce,uint256 revocations,address signer,uint256 signerEpoch,uint256 deadline)` |
| `REGISTER_USER_TYPEHASH` | `0x08047a61f834abacb9e6933736e7a17a949d36d81dc3bb91db74050ad7d1d06b` |

| Field | Value when the call lands | Moves when |
| --- | --- | --- |
| `reserve` | The Reserve to register on | Never |
| `leaf` | `H2(owner, userKeyExchange)`, computed off-chain | Never |
| `leafNonce` | `Reserve(reserve).leafNonce(leaf)` | The leaf is registered or removed |
| `revocations` | `revocations(reserve, leaf)` on the registrar | A `USERS` holder calls `revoke(reserve, leaf)` |
| `signer` | The account that signed | Never |
| `signerEpoch` | `Reserve(reserve).permissionEpoch(USERS, signer)` | The signer loses `USERS` |
| `deadline` | The last valid timestamp, inclusive | Never |

`userKeyExchange` stays off-chain and must be a full-entropy key-exchange output, or the leaf can be brute-forced.

`registerUserDigest(reserve, leaf, signer, deadline)` returns the digest to sign, with the three counters filled in at their current values: `keccak256("\x19\x01" || domainSeparator() || structHash)`.

A signer can produce the same digest with viem's `signTypedData`. This assumes `publicClient`, `walletClient`, `account`, `reserve`, `registrar`, `leaf` and `deadline` are already defined:

```ts
import { keccak256, parseAbi, toHex } from "viem";

const reserveAbi = parseAbi([
  "function leafNonce(uint256 leaf) view returns (uint256)",
  "function permissionEpoch(bytes32 role, address account) view returns (uint256)",
]);
const registrarAbi = parseAbi([
  "function revocations(address reserve, uint256 leaf) view returns (uint256)",
]);
const USERS = keccak256(toHex("USERS"));

// All three counters can move, so read them just before signing.
const [leafNonce, signerEpoch, revocations] = await Promise.all([
  publicClient.readContract({ address: reserve, abi: reserveAbi, functionName: "leafNonce", args: [leaf] }),
  publicClient.readContract({ address: reserve, abi: reserveAbi, functionName: "permissionEpoch", args: [USERS, account.address] }),
  publicClient.readContract({ address: registrar, abi: registrarAbi, functionName: "revocations", args: [reserve, leaf] }),
]);

const signature = await walletClient.signTypedData({
  account,
  domain: {
    name: "MistReserveRegistrar",
    version: "3",
    chainId: await publicClient.getChainId(),
    verifyingContract: registrar,
  },
  types: {
    RegisterUser: [
      { name: "reserve", type: "address" },
      { name: "leaf", type: "uint256" },
      { name: "leafNonce", type: "uint256" },
      { name: "revocations", type: "uint256" },
      { name: "signer", type: "address" },
      { name: "signerEpoch", type: "uint256" },
      { name: "deadline", type: "uint256" },
    ],
  },
  primaryType: "RegisterUser",
  message: { reserve, leaf, leafNonce, revocations, signer: account.address, signerEpoch, deadline },
});
```

## Registering

```solidity
function registerUser(
  address reserve,
  uint256 leaf,
  uint256 deadline,
  address signer,
  bytes calldata signature
) external returns (uint256);
```

Anyone can call it. It checks, in order:

| Check | Revert |
| --- | --- |
| `block.timestamp <= deadline` | `Registrar: signature expired` |
| `signer` holds `USERS` on `reserve` | `Registrar: missing users permission` |
| The signature is valid for `signer` over the digest at the current counters | `Registrar: invalid signature` |

A signature whose leaf nonce, revocation count or signer epoch has moved since it was made no longer matches the digest, and fails the last check.

It then calls `Reserve(reserve).addUser(leaf)` and returns the leaf. The Reserve emits `UserRegistered(leaf, index, root)` with the index that `removeUser` needs, and pushes its new users root to the Chamber, which changes the shared zkState root.

Whoever holds a signature chooses when, before the deadline, the registration lands.

## What voids a signature

| Event | Effect |
| --- | --- |
| The registration lands | `leafNonce` moves, so the signature cannot register the leaf twice |
| The member is removed | `leafNonce` moves, so no signature made before the removal can put the member back. Re-registering needs a new signature |
| A `USERS` holder calls `revoke(reserve, leaf)` | `revocations` moves, cancelling every outstanding signature for the leaf, from every signer, with any deadline. Signatures made afterwards work |
| The signer loses `USERS` | `signerEpoch` moves, on a revoke of its grant or when it hands the admin role on. Granting the role again does not revive its old signatures |
| The deadline passes | The call reverts with `Registrar: signature expired` |

## Signatures

| Signer | Accepted |
| --- | --- |
| An account with no code | ECDSA only. A malformed signature reverts with its reason: `Registrar: bad signature length` (not 65 bytes), `Registrar: malleable signature` (`s` above half the curve order) or `Registrar: bad signature v` (not 27 or 28) |
| A contract | ECDSA first. If that does not recover the signer, ERC-1271: `isValidSignature(digest, signature)` must return `0x1626ba7e`. Only the first return word is read |

The branch is chosen by whether `signer` has code when the call lands. An account with an EIP-7702 delegation has code, so a malformed ECDSA signature from it falls through to ERC-1271 instead of reverting with its reason.

ECDSA is implemented in the contract because the Paris EVM target lacks `mcopy`. The signature is ECDSA over secp256k1 and is not post-quantum.

:::caution[ERC-1271 signers are trusted]
The registrar accepts whatever a `USERS` holder with code approves. Grant `USERS` only to contracts whose `isValidSignature` cannot approve arbitrary digests.
:::

## Revoking

```solidity
function revoke(address reserve, uint256 leaf) external;
```

Any `USERS` holder on `reserve` can call it, or it reverts with `Registrar: missing users permission`. It increments `revocations(reserve, leaf)` and emits `SignaturesRevoked(reserve, leaf, revocations)`. Every signature for that leaf made before the call stops working, whoever signed it.

Removing a member is not done here: a `USERS` holder calls `Reserve.removeUser(index)` directly. See [Reserve](/contracts/reserve/#users-tree).
