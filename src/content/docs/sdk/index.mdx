`@mistcash/sdk` is the TypeScript SDK for MIST on EVM. It builds spend proofs on the user's device, in Node or in a browser, and wraps the calls to the Chamber, Reserve and registrar contracts.

:::caution[These pages document the next SDK release]
They describe the SDK as it will ship, built against mistcash/core `fa7b92d`. The published `@mistcash/sdk@0.6.0-beta.1` predates it and targets an earlier contract interface, so calls such as `join` and `setReserveScreener` fail against current contracts. [Migrating from 0.6.0-beta.1](/sdk/migrating/) lists every difference.
:::

## What the client does

`MistClient` takes an address book, a chain adapter and a prover. It covers each role in the protocol.

| Role | Methods |
| --- | --- |
| Depositor | `deposit`, `setDepositRefundTo`, `reclaimDeposit`, `refreshScreening` |
| Member | `join`, `spend` for a private payment or a withdrawal |
| Reserve admin and permission holders | `grantPermission`, `revokePermission`, `transferAdmin`, `acceptAdmin`, `setAssetMinDeposit`, `removeUser`, `revokeRegistration`, `updateAuditorKey`, `setReserveScreener` |
| Key holder | The Reserve's half of `join`, and `openPayload` to read a member's spend |
| Screener | `queuedDeposits`, `approveDeposits`, `rejectDeposits` |
| Chamber owner | `registerReserve` |

Registration uses a post-quantum key exchange. The SDK ships X-Wing, a hybrid of ML-KEM-768 and X25519, as `encapsulate`, `decapsulate` and `deriveUkx`. The protocol does not fix the exchange, so a Reserve can use another. The proofs are Groth16 and the registration signature is ECDSA or ERC-1271, so neither is post-quantum.

## Limits to know first

- `secretOf` derives a MIST secret from a private key and is for development only. A browser wallet never exposes its key, so an application derives the secret from a wallet signature.
- The prover's note amount is a `uint64`, so one note holds at most about 18.4 units of an asset with 18 decimals. The protocol allows amounts below 2^120. Larger amounts split across notes.
- The client keeps notes and key exchanges in memory. The host persists them, and calls `restoreKeyIndices()` at startup when it passes a `store`. [Notes and keys](/sdk/notes-and-keys/) has the detail.

The [README](https://github.com/mistcash/sdk) in the SDK repository covers bundler configuration for Vite and webpack.
